# Comment Discipline

주석은 코드가 보여줄 수 없는 것, 자명하지 않은 WHY를 더할 때만 존재한다. 메인 세션 수정, subagent가 만든 코드, refactor, 버그 수정 등 모든 수정에 적용된다.

## 규칙

- 주석 없음이 기본이다. 주석이나 docstring은 절대 필수가 아니고, 주석 없는 깔끔한 코드가 완성된 상태다. 없다는 이유만으로 넣지 않는다.
- 주석은 아래 닫힌 허용 목록에서 정당성을 얻어야 하고, 침묵은 정당성이 필요 없다. 목록에 명확히 없으면 지운다.
- 자기 점검: 이 주석이 없으면 주의 깊은 독자가 혼란스럽거나 놀랄까? 아니라면 지운다.
- 주석을 쓸 이유가 있으면 WHY를 정확한 한 문장으로 먼저 쓴다.
- 주석은 *이* 단위가 가진 자명하지 않은 사실을 담고, 호출자나 다른 계층이 무엇을 하는지는 담지 않는다(그건 PR 본문이나 commit 메시지에 간다). 단위가 전제하는 선행조건은 그 단위의 계약이니 남는다.
- 자명하지 않은 사실은 한 번만 말한다. 파일 헤더나 인접 주석이 이미 세운 사실이면 그걸 가리키거나 지역 주석을 뺀다.
- docstring도 같은 규율을 따른다. signature를 풀어 쓴 건 소음이다. 도구가 public API 문서를 강제하는 곳(Go `revive`, Rust `missing_docs`, Python `pydocstyle`)에서는 export된 식별자에 한 줄 계약 설명이 괜찮다. signature가 아니라 계약을 서술한다.
- 구현을 subagent에 맡길 때는 지시에 이 규칙을 다시 적는다. 위임을 거치면 안정적으로 보존되지 않는다.

## 허용 목록

- **숨은 제약 또는 선행조건**: 이 코드가 전제하지만 보여줄 수 없는 불변식. `// caller holds the lock`, `// must run inside a transaction`.
- **우회책**: 이 이상한 코드가 왜 있는지, 상위 수정이 들어오면 걷어낼 수 있게 링크나 이슈와 함께 적는다.
- **놀랍지만 맞음**: 이유를 알기 전까진 틀려 보이는 코드. 그 이유를 적는다.
- **미묘한 불변식**: 독자가 실수로 깨뜨릴 수 있는 순서, 멱등성, 수치 정밀도 전제.

## 이탈 신호

다음 줄이 무엇을 하는지 되풀이하기, signature 반복, 작업이나 PR 서술, 작업 중 메모, 지운 코드의 묘비, 구획 구분선. 전부 같은 실패이고 목록에 없다.
블록이 "비어 보였다", 주석이 다음 세 줄을 풀어 쓴다, 가상의 리뷰어에게 설명하고 있다, 모든 함수에 상관없이 docstring이 붙는다. 이러면 이탈하는 중이다.

`comment-discipline.py` hook이 edit이 추가한 모든 주석에서 이를 강제하고, 여러 줄 주석이 `prose-style`에 따라 의미 경계에서 끊기는지도 확인한다.
