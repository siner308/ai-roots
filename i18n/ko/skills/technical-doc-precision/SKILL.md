# Technical Doc Precision

기술 문서는 그대로 따라 할 사람이 읽으므로 조건과 값, 경계가 글을 다듬는 동안에도 살아남아야 한다.

## 규칙

- 고칠 때 행위자, 대상, 조건, 시점, 순서, 수량, 부정, 예외, 의무 수준을 원래대로 지킨다. 원문이 모호하면 한쪽으로 읽지 말고 작성자에게 물을 항목으로 남긴다. ❌ "환기구가 닫혔는지 확인한다"를 "환기구를 닫는다"로, "반환 전에 기록한다"를 "반환 후 기록한다"로 고친다 ✅ 짧아진 문장도 여전히 확인하고, 여전히 먼저 기록한다.
- 논리 범위는 말로 쓴다: "모두", "하나 이상", "정확히 하나". 중요한 조건을 "및/또는", "A/B", "등"으로 줄이지 않는다. "A이면 B"와 "A인 경우에만 B"는 다른 주장이므로 충분조건을 필요조건으로 강화하지 않는다.
- 값이 없을 때 각각 어떻게 되는지 적는다. 생략, 빈 문자열, 빈 목록, null, false, 0은 서로 다른 입력이다. ❌ "`MAX_LOANS`를 설정하지 않으면 무제한" (실제로는 `0`도 무제한이고 빈 문자열은 오류) ✅ 경우마다 한 줄씩.
- 범위에는 경계와 기준을 붙인다: 양 끝을 포함하는지, 어떤 단위로 무엇을 기준으로 재는지. ❌ "10도에서 20도 사이" ✅ "작업대 센서 기준 10 °C 이상 20 °C 이하".
- 시간에는 기준을 붙인다: 벽시계인지 monotonic인지, UTC인지 현지 시각인지, 어떤 사건부터 세는지, 어떤 구간 단위인지. ❌ "한 시간 안에 3번 재시도" ✅ "첫 실패부터 시작하는 60분 이동 구간 안에서 최대 3번 재시도".
- 자리표시자는 실제 값으로 착각하지 않게 표시하고(`<catalog-id>`), 실제 값은 그대로 쓴다. 그럴듯한 가짜 값이 들어간 명령은 그대로 붙여 넣어져 실행된다.
- 명령과 출력은 서로 다른 code block에 두고, 명령 블록에는 프롬프트 문자를 넣지 않는다. 그래야 명령을 복사하면 명령만 복사된다.
